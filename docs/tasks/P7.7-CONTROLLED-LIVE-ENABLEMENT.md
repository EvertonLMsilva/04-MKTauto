## Direitos e persistência

O operador concedeu separadamente uso comercial apenas neste teste. MediaAuthorization existente recebe operationScope opcional: só libera fal_ai para a operação exata. Não libera outro teste, workflow comercial ou QC final. Registros históricos permanecem imutáveis. Trata-se de declaração documentada do operador, não parecer jurídico ou PASS semântico.

O WebP local é limitado e vinculado ao hash; a data URI transmite os mesmos bytes e seu hash é validado pelo adaptador. Preparação/briefing são reconstruídos, com gates de direitos/modelo e reserva fal existentes. Antes do POST, Finance faz reserva global e transição atômica RESERVED → SUBMITTING sob operationId fixo. Replay, concorrência ou restart não autorizam segunda chamada. O estado torna-se UNKNOWN inclusive após reconhecimento: request id não comprova cobrança. Liquidação exige evidência real, sem custo zero ou recibo fictício.

FalGenerationRepository preserva request id, estado, proveniência e materialização. Timeout sem id exige reconciliação e nunca autoriza retry. Recuperação consulta o mesmo id por GET. Falha de um gate posterior à reserva fal pode exigir reconciliação conservadora, sem cobrança presumida.

QC temporal, movimento real do sujeito, fidelidade, áudio/alinhamento e aprovação humana continuam independentes. Provider concluído não é PASS. Publicação permanece fora deste fluxo.
