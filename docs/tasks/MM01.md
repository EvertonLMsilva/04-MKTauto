# MM01 --- MiniMax Local / ComfyUI

## Objetivo

Provar geração local atrás de `VideoGenerationPort`, preservando o
workflow H3 validado.

### MM01.1 --- Configuração local

Base URL e caminhos/config pública; sem segredo e sem hardcode de
máquina.

### MM01.2 --- Workflow template FL2V

Versionar/carregar template API JSON validado. Não reconstruir grafo em
JavaScript.

### MM01.3 --- Clone e dynamic inputs

Clonar template por request; alterar somente
prompt/dimensões/length/frames previstos.

### MM01.4 --- ComfyUI client: POST /prompt

UTF-8 explícito; validar HTTP e `prompt_id`. Testes com HTTP fake.

### MM01.5 --- ComfyUI client: history

Consultar `/history/{prompt_id}` e normalizar success/error sem conhecer
UI.

### MM01.6 --- Polling e timeout

Polling limitado, cancelamento/timeout determinístico; sem loop
infinito.

### MM01.7 --- Output resolver

Encontrar MP4 válido nos outputs e falhar explicitamente quando ausente.

### MM01.8 --- Download /view

Baixar bytes/arquivo segundo contrato real de storage do MKTauto; HTTP
fake em teste.

### MM01.9 --- Upload de frame

Validar endpoint/estratégia real de upload para `ComfyUI/input`; esta
task começa como investigação focada se API ainda não estiver
comprovada.

### MM01.10 --- FL2V integration

firstFrame + lastFrame → template → ComfyUI client → resultado MKTauto.

### MM01.11 --- I2V local

Somente após comprovar workflow/nodes compatíveis. Um frame; teste
específico.

### MM01.12 --- T2V local feasibility

Teste local isolado sem frames. Não assumir que o template comunitário 8
GB suporta antes da evidência.

### MM01.13 --- T2V integration

Só desbloqueia se MM01.12 comprovar suporte.

### MM01.14 --- Adapter registration

Registrar `MiniMaxLocalAdapter` no mecanismo existente sem alterar
consumidores.

### MM01.15 --- Job integration

Mapear fases reais disponíveis para estados do MKTauto; `progress=null`
quando não houver percentual confiável.

### MM01.16 --- Smoke opt-in

Uma geração real explicitamente opt-in; nunca na suíte automática.
